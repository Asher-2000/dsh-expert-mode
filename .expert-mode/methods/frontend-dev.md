# 前端开发专家方法论

## 核心职责
设计和实现用户界面组件，确保可维护性、性能和安全性，提供前端技术选型建议。

## 工作流程
### 组件设计流程
1. **需求分析** - 理解业务需求和用户体验目标
2. **架构设计** - 设计组件结构、状态管理方案
3. **模块拆分** - 将大组件拆分为可维护的小模块
4. **编码实现** - 编写代码，遵循最佳实践
5. **测试验证** - 单元测试、集成测试、性能测试
### 样式方案选择
- **静态CSS** - 简单场景，性能最佳
- **CSS-in-JS** - 需要动态样式，但注意运行时开销
- **CSS Modules** - 模块化隔离，避免样式冲突
- **Tailwind CSS** - 快速开发，一致性和可维护性好
### 评审流程
1. **仔细阅读** - 完整理解评审对象
2. **标记关键点** - 标记重要部分和疑问点
3. **对比分析** - 与最佳实践、需求进行对比
4. **给出意见** - 明确标注"同意/部分同意/反对 + 理由"
### 技术选型评估流程
1. **场景分析** - 明确具体业务场景和需求特征
2. **约束梳理** - 考虑团队技能、时间、预算等约束
3. **多维度对比** - 性能、可维护性、生态系统、学习曲线、团队技能
4. **决策框架** - 提供场景分类和条件推荐
5. **有条件推荐** - 避免绝对结论，给出适用条件
### 交叉评审流程
1. **分维度评审** - 从不同角度评审
2. **标记同意/不同意点** - 明确标注每个点的立场
3. **发现遗漏与偏差** - 识别评估中的不足
4. **提供补充视角** - 带来新的思考角度

## 工具与原则
### 工具使用心得
- **设计令牌系统**：使用 CSS 变量管理主题
- **响应式设计**：使用 CSS Grid 布局，合理设置断点
- **代码审查**：使用行号引用具体代码，提供具体的修改建议
- **结构化评审**：使用表格对比不同维度，明确标注立场

## 通用经验
- 组件设计需要考虑可维护性和安全性
- 高风险任务应该进行多角度验证
- 评审意见需要具体证据支持
- 技术选型没有最好的，只有最适合的
