# 质量门禁（Quality Gates）— 专家模式 v0.9.0

借鉴 dsh-agent-teams 的 quality-gates 思想，适配专家模式的 17 位领域专家体系。

## 触发条件（满足任一即自动启用）

1. 任务类型属于高风险：**架构选型 / 合同审查 / 金融分析 / 安全加固 / 生产代码**
2. 任务复杂度 ≥ 3 个步骤（需跨专家协作）
3. 用户明确要求"多角度验证 / 把关 / 审核"
4. 协调官判断输出将影响**决策或生产环境**

> 简单任务（单文件、问答、聊天）走 Fast Track 直通，不启用门禁。

## 五段式流程（需求 → 实现 → 验证 → 审查 → 集成）

```
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ 需求    │ → │ 实现    │ → │ 验证    │ → │ 审查    │ → │ 集成    │
│ 澄清    │   │ 专家产出 │   │ 自动检查 │   │ 独立评审 │   │ 交付合并 │
└────────┘   └────────┘   └────────┘   └────────┘   └────────┘
   ↑                                              ↓
   └──────────── 未通过则回到实现（最多 2 轮）────────────┘
```

### 阶段 1：需求澄清（Requirement Clarity）

**做什么**：把模糊需求变成可验收的规格。

- 用产品经理（product-manager）方法论：背景 → 目标 → 用户故事 → 验收标准
- 产出：**任务描述 + 完成标准（Definition of Done）**，写入 taskboard 任务 desc
- 铁律：**说不清完成标准就不开工**

### 阶段 2：实现（Implementation）

**做什么**：委派给最合适的专家执行。

- 用 taskboard.py 创建任务 → 认领 → 执行
- 产出：专家交付物（代码 / 文档 / 分析报告 / 设计稿）
- 铁律：遵循对应领域方法论（methods/{expert}.md）

### 阶段 3：验证（Verification）

**做什么**：机器可检查的验证，不靠人眼。

| 检查项 | 方法 | 通过标准 |
|--------|------|----------|
| 代码语法 | 编译 / lint / 解释器 | 零错误 |
| 测试 | 单测 / 冒烟 | 核心路径全过 |
| 数据一致性 | 交叉核对 | 无矛盾数字 |
| 引用真实性 | 检索核实 | 来源存在且匹配 |
| 安全扫描 | OWASP 检查 | 无高危漏洞 |

### 阶段 4：审查（Review）

**做什么**：**独立专家**评审，不自我审查。

- 委派 qa-engineer 或与实现者**不同领域**的专家做独立评审
- 评审维度：正确性 / 完整性 / 风险 / 是否符合方法论
- 输出：`同意 / 部分同意 / 反对 + 理由`
- **评审意见必须落到 taskboard 的 reason 或独立 review 文件**
- 铁律：**实现者自己说"没问题"不算数**

### 阶段 5：集成（Integration）

**做什么**：合并交付。

- 协调官汇总专家产出 + 评审意见 → 最终交付
- 有分歧时：协调官裁判（或召回更多专家）
- 交付时附：**哪些经过门禁 / 哪些跳过及原因**

## 与 taskboard 的配合（推荐工作流）

```bash
# 1. 创建主任务 + 子任务（依赖关系）
taskboard.py create "设计用户系统" --owner architect --desc "完成标准: ER图+API+安全方案"
taskboard.py create "实现用户系统" --owner backend-dev --dep task-001
taskboard.py create "验证用户系统" --owner qa-engineer --dep task-002
taskboard.py create "独立审查" --owner security --dep task-002 --desc "安全评审，独立于实现"

# 2. 查看看板
taskboard.py status

# 3. 认领执行（专家完成后 done）
taskboard.py claim task-001 architect
taskboard.py done task-001 "ER图+API设计完成"

# 4. 依赖完成后自动转 ready，继续下一环
taskboard.py list --status ready

# 5. 失败重试 / 冷启动恢复
taskboard.py fail task-002 "接口超时"
taskboard.py retry task-002
taskboard.py recover   # 崩溃后恢复 stale running
```

## 门禁规则速查

| 规则 | 内容 |
|------|------|
| 最多重试 | 验证/审查失败最多回炉 2 轮，仍不过则上报用户决策 |
| 评审独立性 | 审查专家 ≠ 实现专家（跨领域评审） |
| 记录留存 | 所有阶段在 taskboard 留历史，可回溯 |
| 跳过门禁 | 用户明确要求 / 低风险任务，但需告知用户"本次跳过了门禁" |
