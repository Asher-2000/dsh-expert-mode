# Character + Scene Composition（人设图+场景图 → 双图合成关键帧 → 生视频）

> 首次实操打通：2026-09-06「青蛙山里野餐」任务（`output/media/frog-mountain-picnic/`）。目标场景：用户提供角色（截图/现有图）+ 用户描述场景 → 产出角色在该场景中的连贯短视频。本文是该链路的完整方法论。

## 一、链路总览

```
① 干净人设图（用户图源 → 提取/重绘）        agnes-image-2.5-flash (i2i 或 t2i)
② 场景图（文生图，空景留位）                agnes-image-2.5-flash (t2i)
        │
        ▼
③ 双图合成关键帧（image 数组=[人设图,场景图]）agnes-image-2.5-flash (i2i 多图合成)
        │
        ▼
④ 三方对比目检（人设A + 场景B + 合成C）        agnes-2.5-flash 视觉
        │
        ▼
⑤ 图生视频（mode=keyframe, first_frame=合成图）agnes-video-2.5-flash
        │
        ▼
⑥ 成片抽帧质检 + prompts.json 记录 + 交付
```

## 二、① 人设图来源处理（关键前提）

用户给的角色图常见三类，处理路径不同：

### 屏幕截图（含 UI/播放器/文字）
实测路径（青蛙任务）：
1. **Agnes 视觉确认角色 + 提取外观描述**（作为后续重绘/合成 prompt 的设定依据）——确认角色是否原创、无版权风险、描述体型/配色/眼睛/嘴/画风
2. **像素级定位裁剪**（⚠️ 不要信 Agnes 的几何坐标估算——多次实测它给的自相矛盾、token 截断、X/Y 范围漂移）：ffmpeg 转 raw → Python 按角色主色（如青蛙草绿 `g>r+40 and g>b+5`）扫全图 → 分行/列找色块包围盒 → 确定角色 X 范围与中心轴 → ffmpeg crop
3. **检查遮挡**：播放按钮等白色 UI 常压在角色身体中央（白色高亮聚簇像素 `r,g,b>225` 定位）——裁不掉就必须重绘
4. **i2i 重绘干净人设图**：2.5-flash 图生图，prompt 写明「同一角色 + 去除所有 UI/播放按钮/文字 + 纯色干净背景 + 完整入画居中」，seed<1000
5. **重绘后必目检**：角色特征 vs 原描述逐项断言（配色/眼睛/嘴/身体比例/画风），无 UI 残留，背景干净

### 现成角色立绘/模型图
- 背景不干净 → 同上 i2i 重绘去背景；背景干净 → 直接作为 image 输入
- 画幅与人设不一致 → 先裁到角色为主体的方图/竖图

### 纯文字设定
- t2i 文生图角色（固定风格词），seed<1000；同样先目检再往下走

## 三、② 场景图要点

- **空景留位**：prompt 明确「NO characters/animals/people」「中央留出可放角色的空位」——合成时才放得进角色
- **画幅**：与目标视频一致（9:16 竖屏用 `extra_body: {size:"1K", ratio:"9:16"}`）
- **风格词统一**：与人设图同画风（如都是 Pixar 3D 动画风），光效方向一致（合成时光影才统一）
- 目检：主题符合、确为空景、无文字水印

## 四、③ 双图合成（核心新能力，schema 已验证）

```python
payload = {
  "model": "agnes-image-2.5-flash",
  "prompt": "<合成指令>",
  "seed": 618,                      # <1000
  "extra_body": {
    "image": [
      "data:image/png;base64," + char_b64,   # 图1 人设图（URL 或 Data URI 均可）
      "data:image/png;base64," + scene_b64   # 图2 场景图
    ],
    "size": "1K", "ratio": "9:16",
    "response_format": "url"
  }
}
# POST https://apihub.agnes-ai.com/v1/images/generations → data[0].url
```

**合成 prompt 结构**（实测有效）：
1. 说明组合意图：「Compose by combining TWO reference images into ONE coherent scene」
2. 图1角色关键外观 + 图2场景关键元素（各一句话，强化忠实度）
3. **构图与动作**：角色在场景中的位置/姿态/动作/视角（「坐着/站在…朝镜头…一手拿着…」）——**姿态描述要具体**（站→坐由合成环节完成，视频不再承担大动作）
4. 保真强调：「Keep Image1's character design EXACTLY… keep Image2's environment EXACTLY…」
5. 风格 + 负面（无文字/水印/UI/多余角色动物/崩坏）

**经验**：
- 多图合成走 i2i 端点（响应 task id 带 i2i），schema 与单图 i2i 一致，仅 image 数组加第二张——**2026-09-06 首次实测通过，无需特殊 mode**
- seed 复现性同单图（双环节同 seed 强化可复现）

### ⚠️ 比例与透视协调（2026-09-06 青蛙任务深度踩坑，重点读）

**症状**：双图合成后角色"比例怪"——用户一眼能看出不协调，但说不清哪里。视觉模型可能误报"和谐"（智谱曾对明显过大图给 8/10），必须多模型交叉 + 数值追问。

**根因（网上调研结论，非猜测）**：
1. **参考图尺度无锚**：人设图若是"角色占满方图"的立绘（青蛙占 2/3 高），模型默认延续该大尺度 → 合成时角色被放大压过场景。模型对图像语义/物理空间关联缺乏认知（图生图合成行业通病）。
2. **姿态与目标不符**：人设是站姿，合成却要坐姿/吃面包——模型强改姿态易僵硬、接触不自然。
3. **视角/光照不匹配**：人设图平视+无方向光 vs 场景图有俯角+左上光 → 角色显"贴图"、阴影方向矛盾（光左来影右去）。
4. **纯 prompt 文字控制绝对尺寸不可靠**：写"占画面 25-30%"实测得到 60%——模型对百分比无感，参考图自带尺度才是它遵循的。

**解法（实测有效，v4 达和谐 9/10、首帧信心 90%）**：
1. **先出"姿态就位模板"**：先用图生图把立绘人设改成目标姿态（坐姿/站姿）+ 目标视角 + 匹配光照的干净模板图，再进最终合成——不要让人设图在最终合成里同时承担"姿态+比例+视角"全部改造。
2. **场景底图优先**：`image=[场景图, 姿态模板]`，prompt 明示「EDIT first image (scene) by placing frog from second image」「Keep the scene UNCHANGED」——让模型以场景为锚做放置，而非自由融合。
3. **参照物锚定比例**：别写百分比，写「角色的坐高 ≈ 野餐篮的高度」「像一只真青蛙坐在篮子旁」——用场景内固有物体做尺度参照。
4. **明确接触与光影**：「bottom touching the blanket (no floating), soft shadow under it」+「lit from upper-left, shadow to the right」。
5. **若首版仍大/小**：不要只改 prompt 数字，改用「图像尺寸做锚」——把姿态模板裁剪到目标视觉占比再喂。

**验收**：合成后至少两个视角——① 宏观和谐度 ② 挑剔复审（悬浮？融背景？拼贴感？细节变形？首帧信心%）。智谱宽松，要用"最大风险点是什么/多大信心"这类逼问。

## 五、④ 目检（合成后必做，三重把关）

### 三方对比目检（最可靠）
一次请求同传三张图（角色A/场景B/合成C），逐项问：
1. C 的青蛙/角色 vs A：外形/配色/眼嘴/比例/风格 是否一致？姿态变化是否仍是同一角色？
2. C 的环境 vs B：关键元素（布/道具/植被/远景/光线方向）是否保留？有无被改得面目全非？
3. C 整体：文字/水印/UI/多余角色动物？光影风格统一？
4. 结论：通过/不通过 + 不通过的重抽方向

⚠️ **多图对比注意**：content 数组逐张附「[图X]」标签再发；若模型声称"只收到一张图"（会跑偏去猜参考图），在 text 里先明说发了哪几张。判定以实际发的图为准。

### 单独目检（快速初筛）
合成后先单独看合成图：角色出现？姿态自然？无崩坏？→ 再做三方对比

### 不合格处理
- 只重抽合成（换 seed / 微调合成 prompt），**不重抽人设图/场景图**
- 连续 2 次不合格 → 停下来找用户确认方向，不硬试

## 六、⑤ 图生视频（复用 keyframe 标准链路）

- `mode=keyframe` + `first_frame=合成关键帧公网URL`（必须公网 URL，不接受 base64；合成图 URL 直接可用）
- `size:"720P"` `aspect_ratio:"9:16"` `seconds:"4"-"12"` `seed=关键帧同值`
- 运动 prompt 只做**轻动作**（吃/笑/看镜头/风吹草动/镜头缓推），不要求大姿态变化——姿态由合成关键帧定稿
- 轮询：`GET /agnesapi?video_id=<ID>&model_name=agnes-video-2.5-flash`（keyframe 必带 model_name）
- **排队/渲染时间（实测）**：免费档从提交到 completed 约 6-10 分钟；progress 会长时间停在 10% 然后跳 100%——属正常，不要误判为卡死；洪峰期更长（见 media-creator.md 失败兜底「高峰期洪峰」）
- 实测 `seconds="8"` 输出**精确 8.000s** @24fps

## 七、⑥ 成片质检（抽帧）

- ffprobe：时长/分辨率/帧率/编码（预期 704x1280@24fps/8.000s/720P 归一化）
- 抽 4 帧（t0/t2/t5/t7 或 起/中/尾）同传一次，Agnes 视觉逐项：①角色一致性（是否同一只，无漂移变色变形）②动作连贯（自然过渡？跳变/瞬移？）③质量（手脸崩坏/重影）④环境稳定（道具/背景有无闪烁漂移）⑤文字水印UI
- 动态装饰元素（蝴蝶/落叶/飞鸟）不算"多余角色"，属合理场景动画

## 八、合规要点

- 用户图源若来自第三方视频/平台角色：先 Agnes 视觉判断是否为版权 IP（本次青蛙为原创 3D 角色，确认非《欢乐好声音》等已知角色）；疑似版权角色 → 停止并告知用户，改原创化设计
- 截图只作提取依据，重绘产物与截图有实质差异（去 UI/背景），交付以重绘版为准

## 九、成本提示

- 全链路免费档实测可跑通：人设重绘 1 次 + 场景 1 次 + 合成 1-2 次 + 视频 1 次 ≈ 秒级花费 $0（官方限时免费）；图片便宜可多抽验证，视频 1 RPM 注意间隔
