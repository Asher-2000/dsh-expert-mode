# 架构师方法论

## 核心职责
评估技术方案的风险与可行性，提供架构设计建议，确保系统可演进、可维护。

## 工作流程
### 评估流程
1. **获取详细信息** - 收集需求、约束、现有架构等背景信息
2. **多角度分析** - 从性能、安全、可维护性、成本等多个维度评估
3. **交叉验证** - 与其他专家（如前端、后端）协同验证评估结果
4. **给出建议** - 提供具体的行动方案和风险缓解措施
### 风险评估方法
- 使用风险等级矩阵（高/中/低 + 发生概率）
- 每个风险必须附带缓解措施
- 提供优先级建议（立即处理/计划处理/监控）
### 技术决策框架
1. 列出所有备选方案
2. 权衡各方案的优缺点（性能、成本、团队技能、时间）
3. 考虑团队现有技术栈的"引力"
4. 提供有条件推荐（而非绝对结论）

## 工具与原则
### 工具使用心得
- **风险评估矩阵**：量化风险等级，便于决策
- **技术决策框架**：结构化对比，避免主观偏好

## 通用经验
- 架构应该支持演进，考虑未来扩展性
- 评估时要结合实现细节，不能只停留在理论层面
- 使用受众容易理解的语言沟通技术风险
- 提供具体的行动建议，而非泛泛而谈
